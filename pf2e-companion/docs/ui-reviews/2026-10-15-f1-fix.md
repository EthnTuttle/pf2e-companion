# UI Review Findings: F1 fix — bottom tabbar overlap (`/table/play`, all viewports, both themes)
**Date:** 2026-10-15
**Finding:** `docs/ui-reviews/2026-10-14-first-pass.md` § Major — F1
**Screenshots (post-fix):** `shots/table-play-gm/mobile-dark.png`, `shots/table-play-gm/desktop-light.png`, `shots/table-play-player/mobile-dark.png` (composer now fully above the tabbar); `shots/encounter/desktop-light.png` (unchanged — see harness note)
**Changed files:** `src/routes/+layout.svelte`, `src/routes/table/play/+page.svelte`, `tests/e2e/mobile.spec.ts`

## Defect

### High: Fixed bottom tabbar overlapped the `/table/play` chat composer

- **Location:** `.play-surface` height chain (`src/routes/table/play/+page.svelte`), interacting with the fixed bottom tabbar (`src/routes/+layout.svelte`).
- **Observation (pre-fix, measured at real viewports via the harness build):** the tabbar is 52.17px tall at both 390px and 1280px. `.play-surface { height: 100vh }` ignored the sticky topbar (~48px), main's `1rem 1rem 5rem` padding, and the tabbar, so the surface's bottom edge — where the composer lives — landed below the viewport bottom: composer box `[876.2, 958.2]` on an 844px mobile viewport and `[810.2, 847.2]` on an 800px desktop viewport. At scroll 0 the message input was entirely invisible/off-viewport (worst case of the 2026-10-14 evidence); it could only be reached by scrolling the whole page, dragging the play header off-screen.
- **Expected:** the composer pins inside the viewport, fully above the tabbar, at every viewport, without scrolling the page chrome away.
- **Why the plan's noted "main padding-bottom 5rem" was insufficient:** it wasn't — for normal-flow pages. At max scroll, flow content clears the tabbar by 27.6px (content bottom 763.9 vs tabbar top 791.8 at 390px). The one route that bypassed it was `/table/play`, whose `100vh` surface outgrows main's content box by exactly the chrome the padding was meant to guard against.
- **Fix applied:**
  - `+layout.svelte`: route-scoped `class:fullbleed` on `.app` for `/table/play`, pinning `.app` to `height: 100dvh` (`100vh` fallback) so main's content box — which the play surface now fills — already excludes topbar, padding, and tabbar. No visual change on any other route.
  - `table/play/+page.svelte`: `.play-surface` `height: 100vh` → `height: 100%` (+ `min-height: 0`). The play page becomes an app shell: no body scroll on the route; the play panel keeps its own internal scroll. Diagnosis comments live at both edits.

## Harness note — do not re-file: fullPage fixed-element artifact

The 2026-10-14 evidence on flow pages (encounter creature-XP rows +3/+4, vault frontmatter textarea "behind the bar") is a Playwright `fullPage: true` capture artifact: fixed elements are painted at their scroll-0 viewport coordinates inside the grown screenshot, i.e. mid-image on pages taller than one viewport. At real viewports the same content clears the tabbar at max scroll (measurements above). A `position: sticky; bottom: 0` tabbar variant was tried to force bottom-of-image painting; Chromium paints sticky identically mid-image, so it was reverted as no-benefit churn (tabbar stays `fixed`). Before filing tabbar-overlap from a fullPage shot on a flow route, verify at a real viewport — the 5rem bottom padding is the clearance budget and it holds.
